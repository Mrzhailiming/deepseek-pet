# dsh-pet-plugin — 插件详解

这份文档写插件**有哪些玩法**、以及**内部是怎么实现的**：玩法清单、接入方式、事件来源、全部可调的配置项、计算规则、宠物形象、打包校验、以及偏离策划的地方。只想知道怎么装、怎么打包、怎么分发，看 [`../README.md`](../README.md)。

策划原文：[`../pet-auto-feed-plugin-design.md`](../pet-auto-feed-plugin-design.md)。

```
deepseek-pet/
├── dsh-pet-plugin/                  插件包本体（这一整个目录就是分发单位）
│   ├── index.js                     host 半：空实现，只为成为一条活着的 Loader entry
│   ├── lib/client.js                浏览器半：手写产物，宠物 / Combo / 特效 / 鲸鱼 SVG 都在这里
│   ├── cordis.patch.yml             配置层：往 profile 里插一行 Loader 记录
│   ├── scripts/pack.mjs             打包 + 校验（零依赖）
│   ├── test/smoke.mjs               零依赖冒烟测试
│   └── plugin.md                    这份文档
├── pet-auto-feed-plugin-design.md   策划原文
└── docs/                            README 用的效果图 / 录屏
```

`lib/client.js` 是唯一有逻辑的文件（约 3900 行，含 `//#region` 分区：配置 / 样式 / 计算 / store / 视图 / 插件体）。

## 玩法

<img src="../docs/preview.png" width="700" alt="三档连击表现：平时 / 连击 / 星星眼">

这一节是**玩家视角**的功能清单（每条背后的算法见下文「[计算规则](#计算规则)」）。

- **Agent 干活就是在喂它**：你发消息 🥕、模型回一句 🐟、工具跑完一次 🍖，食物从会话里**事件发生的位置**飞过来落到鲸鱼嘴边，跟着冒 `+13 🐠 · 2.0k tok  +3 ⭐` 的飘字。
- **这一口有多大，看 token 消耗量**：小到一株 🌱，大到一整锅 🍲，字号跟着长，飘字里直接写着这一口烧了多少 token。
- **连续动作攒 Combo**：白字 → 金字（震动）→ 彩虹（强震 + 光环），最高档鲸鱼换**星星眼 + O 型嘴**，经验倍率最高 3.0x。
- **顶到满连击开一段暴食**：卡片红边、连击徽标写成 `×3.0 🔥×2`，15 秒内**经验双倍**、食物量再多两成，期间再顶格就续期。
- **它挑食**：最爱工具结果 🍖（同样的 token 多吃三成），但同一种连着喂 9 次就吃腻了（打七五折），换个口味立刻好。所以一轮里穿插着来，喂得最划算。
- **两条进度条**：橙色是饱食度，蓝色是当前等级的经验；攒够 `等级 × 100` 经验升一级。**空闲时会慢慢饿**，所以食物量的大小一直有意义。
- **心情和精力是活的**：`😊 82 · ⚡ 64` 这一行一直在动 —— 干活涨心情、耗精力，空闲回精力，饿过头心情掉得飞快。心情高经验多（0.8x ~ 1.2x），精力见底再打八五折，所以**养得舒服的鲸鱼升级更快**。
- **还有三分心思写在脸上**：🤔 好奇（碰到没见过的文件 / 工具、搜索抓网页）、😤 得意（升级、进阶、解锁成就、技能升级、从一道报错里走出来）、😟 担忧（工具报错、久坐、深夜、饿着）。哪一维顶过 55 就换一副表情 —— 好奇是一边挑眉 + 大眼 + O 型小嘴，得意是眼睛眯成缝 + 内侧压下去的眉毛，担忧是垂眉 + 抿嘴 —— 并在**刚过线那一下**说一句「这是什么？」「我厉害吧！」「我有点担心你」。它们**不碰任何数值**（经验倍率照旧只看心情），每分钟各自消退一点。
- **5 分钟没动静它就睡了**：闭眼、飘 💤，睡着精力回得快三倍、饿得慢一半。你一发消息、喂一口、摸一下头，它立刻醒来打个哈欠。
- **它会说话**：吃到最爱夸一句、吃腻了抱怨一句、升级了炫耀一句、连上了催你别停、吃饱了喊撑、精力见底说困、心情低了要抱抱、饿了喊一句、睡醒打哈欠、暴食时嚷嚷 —— 头顶冒个气泡，两句之间至少隔 4 秒，不会刷成弹幕。二十来种场合每种都有好几句，挑哪句是**算**出来的而不是随机的，所以既不会连着蹦出同一句，行为也照旧可复现。
- **摸头**：点一下头像，冒一颗 💗、涨 6 点心情（1.5 秒冷却）。摸够 50 次有徽章。连着摸三下以上它换一套台词（「还、还要吗…」）。
- **它看着你的鼠标**：瞳孔跟着指针转 —— 幅度只有一点几个像素，表示的是「往哪儿看」而不是「离多远」，鼠标停下两秒就回正。闲过 45 秒它会自己找点事做：打个哈欠、快摆几下尾巴、侧身翻一下、连眨两下眼探个头；挑哪个动作也是**算**出来的。
- **想放哪儿放哪儿**：按住卡片直接拖，松手记住位置，刷新还在那儿；拖到屏幕外也会留一角在视野里。
- **14 枚成就 + 每天三条任务**：第一口、尝遍三味、满连击、大胃王、百万 token、连续三天来看它、连续一周来喂它、跨过 50 次工具报错、任意一门技能满级、把好奇心顶到满格、王冠……解锁时飘一条彩虹大字，卡片上排开徽章墙。每日任务（喂 10 次 / 5 次工具结果 / 打到 7 连击）达成给 30 经验 + 一格零食，点卡片上的 🏅 看面板：状态条、今日进度、技能、记忆、成就格子（没解锁的悬停看条件）。
- **你用哪类工具，它就往哪个方向长**：读写文件长 💻 编码、搜索抓网页长 🔍 探索、跑命令长 🐛 调试、写计划报告长 ✍️ 表达 —— 一次工具调用一点经验，Lv.10 是长期目标。技能**不改任何数值曲线**（食物量 / 经验一点没动），它换来的是下面这两条。
- **它记得你**：常改哪几个文件、最常用哪个工具、常在几点干活、跨过多少次报错，面板上写着 `记忆 · 相处 12 天` / `📄 常改 client.js(9)` / `🕘 常在 21-23 点干活`。相处三天以上，睡醒那句会变成「又见面了，这是第 12 天…」。只记文件名不记路径，表满了会忘掉冷门的那些。
- **它会提醒你**（技能够级才解锁，一分钟最多一句）：同一个文件改到第 3 次 → 「`client.js` 改到第 3 次了，跑个测试？」，第 6 次、第 9 次语气一路加重；连着 3 条工具报错 → 「连着 3 次报错了，先看看上一条错误？」；同一个工具连着挂 → 「`bash` 连着挂了 2 次，换个思路试试？」；终于跑通了 → 「`bash` 终于成了！这道坎跨过去了」。就这四句，宁可少说也不刷屏。
- **它会关心你**（半小时最多一句）：凌晨还在写 → 「这么晚还在写代码？」；一口气干了两小时 → 「歇会儿吧，你坐了好久了」；隔了八小时才回来 → 「你去哪儿了…我等了 9 小时」；再不然就拿它记住的东西跟你搭话 —— 「又是 `client.js` 啊」「又到你干活的点了（21-23 点）」。这几句没有信息量，所以稀有才不烦人，它也永远不会为了说这个把别的话挤掉。
- **越养越大只**：等级带来 4 档形态 —— 幼崽（小、大眼、还不会喷水）→ 少年（喷水柱）→ 成年（大背鳍）→ 传说（金色描边 + 王冠）。体型差了将近两倍，颜色从近乎白的淡蓝沉到海军蓝。跨档那一刻飘一条「进阶 · 成年」，头像外面炸开一圈金环；名字行写着 `深深 · Lv.6 成年`，鼠标悬停看得到还差几级到下一档。
- **饿了你可以亲自喂**：卡片上那颗 🍬 点一下就喂一口。零食是有库存的（5 格、45 秒回一格、离线也在攒），所以点不出等级，也**永远不会饿死**。手喂不算连击、不进 token 统计，刷不出等级也不会污染消耗面板。
- **饿了会提醒**：饱食度只剩 20 以内时饱食条变红、鲸鱼耷脸、糖果按钮开始跳。饥饿封顶就停住，不掉等级也不重置，红条纯粹是催你喂它。
- **点一下卡片**折叠成只剩头像，再点展开；展开时有一行 `消耗 12.3k tok · 🥕2.1k 🐟8.0k 🍖2.2k`，鼠标悬停看心情 / 精力 / 累计喂食次数。折叠状态下 🍬 还在，随时能喂；摸头和拖动也照旧。
- **进度不会因为刷新归零**：等级、经验、累计消耗、成就、今日任务、连续到访、技能、记忆、情绪三维、摆放位置都存在浏览器本地，关标签页也在；离开的这段时间它会慢慢饿、慢慢回精力（最多按 24 小时算），回来先喂一口。多开标签页养的是同一只。想重新养一只：控制台执行 `localStorage.removeItem('dsh-pet-plugin/state')`。
- 系统开了「减少动效」时，所有动画自动关闭 —— 瞳孔跟鼠标和闲下来的小动作**整套不做**（不是关掉动画留着算，是根本不挂监听、不起定时器）。

## 它是怎么接上去的

```
package.json
├── dsh.bundle  ──→ cordis.patch.yml  插入一行 Loader 记录 (id: pet-feed)
└── dsh.client  ──→ exports["./client"] = lib/client.js
                    client-modules 在启动时扫描活着的 Loader entry，
                    发现 platform: "web" 的包就把产物挂到
                    /plugins/dsh-pet-plugin/client.js 并写进 window.__DSH_BOOT__
```

- `index.js` 是 host 半，**空实现**。它存在的唯一理由是让这个包成为一条活着的 Loader entry —— `client-modules` 的扫描以此为前提。
- `lib/client.js` 是浏览器半，**手写产物**（`window.__ModuleLoader__.load({ id, factory })` 的 CJS factory 格式，与 `tsdown.client.ts` 生成的 banner/footer/intro 逐字一致）。因此这个包**没有构建步骤**：`dsh plugin add` 装完即用，不需要 tsdown、不需要联网、不需要 pnpm 的 `allowBuilds` 授权。
- 浏览器半只 `require('react')`，其余全是自带代码；样式用一个 `<style data-plugin="dsh-pet-plugin">` 标签在 factory 里注入一次。

### 事件从哪来

策划里画的「host → 前端 WebSocket Push」这条路走不通：转发白名单 `API_REMOTE_FORWARDED_EVENTS`（`packages/api/remotes/src/remote-events.ts`）是一个编译期常量数组，往里加 `pet/feed` 就必须改仓库。所以喂食桥接器整体下沉到浏览器：

插件用 `ctx.conversationEvents.register()` 注册一个 **state-only 的 Conversation Definition**（不声明 `target`，`publication` 恒为 `"none"`，不产出任何视图节点）。它的 `match(event)` 拿到的是**原始 SessionEvent**，于是三个喂食源直接可读：

| 事件 | 触发源 | token 消耗量 | 基础经验 |
|---|---|---|---|
| `user/message`（且 `source.kind === "user"`） | `user_input` | 可见文本字符数 / 4（估算） | 1 |
| `assistant/message`（且带 `usage`） | `generation` | `usage.inputTokens + usage.outputTokens`（真实） | 2 |
| `tool/result` | `tool_result` | 结果 content 的 UTF-8 字节数 / 4，最少 1（估算） | 3 |

`user/message` 只认 `source.kind === "user"`：插件注入的上下文也是 `user/message`，那不是用户输入。`assistant/message` 只在 adapter 报了 `outputTokens` 时才算一次 generation，取 **input + output** 的全量消耗——上下文越长，这一步喂出去的分量越大。另外两个源没有 `usage`，只能按长度粗估。

还有第四类事件，**只观察、不喂食**：

| 事件 | 读什么 | 用来做什么 |
|---|---|---|
| `tool/call` | `name`（工具名）、`arguments` 里的 `file_path` | 技能经验、记忆里的文件 / 工具 / 时段表、「这文件改到第 3 次了」 |
| `tool/result` 的 `error` | 有没有报错 + `toolCallId` 回查的工具名 | 错误连击、「克服过的困难」 |

`tool/call` 走**同一道**幂等闸门（下一节），但刻意不进 combo、不进 token 统计、不动饱食 / 心情 / 精力、不算「今天来喂过了」：一轮工具循环里 call 与 result 各记一次账的话，连击会翻倍、消耗面板会重复计数，现有的平衡全部作废。它只长技能和记忆 —— 这也是整套玩法里**唯一**知道「你刚才在干什么」的数据来源，三个喂食源只看得见「烧了多少 token」。

### 为什么不会被历史刷屏

Conversation 引擎会在打开会话、翻历史、边界解析、插件集变化时**重新折叠**同一批事件，`start` 因此会对同一条事件被反复调用。插件用一道幂等闸门兜住：

1. **新鲜度**：`Date.now() - event.time > 30s` 的事件一律不喂。打开一个旧会话时整段日志会被折叠一次，这一条挡掉了它。
2. **去重**：键取 `seq + time + type` 复合（`seq` 只在会话内单调，跨会话不可比），只保留新鲜度窗口内的键。

## 调参：浏览器侧配置

宠物名字、连击窗口、食物量、要不要特效……都能改。配置走 `localStorage`，在页面控制台执行后**刷新生效**：

```js
localStorage.setItem('dsh-pet-plugin/config', JSON.stringify({
  comboWindowMs: 3000,   // Combo 窗口（默认 5000）
  maxCombo: 20,          // 最大连击（默认 10，注意会抬高经验倍率上限）
  maxFood: 25,           // 单次最大食物量（默认 30）
  tokensPerFood: 30,     // 曲线起点：约等于第一份食物的 token 量（默认 60，越小吃得越多）
  foodPerDouble: 4,      // token 每翻一倍多给几份食物（默认 2.5）
  hungerRegenPerMin: 0,  // 每分钟回升的饥饿度（默认 2；0 = 只降不升）
  manualFeedEnabled: false,   // 关掉主动喂食，卡片上不再有 🍬（默认 true）
  manualFeedFood: 25,    // 一口零食顶多少饱食（默认 15）
  manualFeedExp: 0,      // 一口零食给多少经验（默认 1；0 = 不给）
  manualSnackMax: 10,    // 零食格数上限（默认 5）
  manualSnackRegenMs: 10000,  // 多久回一格零食（默认 45000；<= 0 = 永远满格）
  hungryAt: 60,          // 饥饿到多少就开始报警（默认 80，即饱食度只剩 20 以内）
  persist: false,        // 关掉进度落盘，回到刷新即重来（默认 true）
  saveDebounceMs: 3000,  // 落盘的合并写窗口（默认 1500）
  offlineRegenCapMs: 3600000, // 离线饥饿最多按多久结算（默认 86400000，即 24h）
  effectsEnabled: false, // 只留宠物卡片，关掉飞行特效（默认 true）
  effectTtlMs: 1500,     // 单条特效时长（默认 2200）
  flyFromConversation: false, // 食物就地飞入，不从会话区飞过来（默认 true）
  freshnessMs: 60000,    // 多久之内的事件才喂（默认 30000）
  petName: '球球',        // 宠物名（默认 '深深'）
  petSpecies: '史莱姆',   // 副标题的种族（默认 '深海小鲸'）
  petAvatar: 'emoji',    // 'whale'（默认）= 二次元鲸鱼；'emoji' = 用下面这个字形
  petIcon: '🐙',         // petAvatar 为 'emoji' 时的头像（默认 🐳）
}))
```

玩法那一堆（心情 / 精力 / 睡眠 / 互动 / 成就 / 任务 / 食性）也在同一个键里，每组都有一个总开关，设成 `false` 就退回没有这条玩法的样子：

```js
localStorage.setItem('dsh-pet-plugin/config', JSON.stringify({
  // 心情 / 精力
  vitalsEnabled: false,      // 关掉 → 两个数字变回静态展示值，卡片上那一行也不渲染（默认 true）
  moodPerFeed: 5,            // 一口饭涨多少心情（默认 2）
  moodPerPat: 10,            // 摸一次头涨多少心情（默认 6）
  moodDecayPerMin: 0,        // 每分钟自然回落的心情（默认 0.4；0 = 只涨不落）
  moodDropPerMinHungry: 1,   // 饿着时每分钟额外掉的心情（默认 2.5）
  moodExpSwing: 0,           // 心情对经验的摆幅（默认 0.4；0 = 心情不影响经验）
  moodSadAt: 50,             // 心情低于多少摆委屈脸（默认 30）
  energyPerFeed: 0,          // 陪 Agent 干一次活耗多少精力（默认 3）
  energyRegenPerMin: 3,      // 每分钟回多少精力（默认 1.2）
  energySleepFactor: 5,      // 睡着时精力回升的倍数（默认 3）
  lowEnergyAt: 10,           // 精力低于多少算「困了」（默认 25）
  tiredExpFactor: 1,         // 困着时的经验折扣（默认 0.85；1 = 不打折）
  // 睡眠
  sleepEnabled: false,       // 关掉 → 永远不睡（默认 true）
  sleepAfterMs: 60000,       // 多久没事件就睡（默认 300000，困着时按一半算）
  sleepHungerFactor: 1,      // 睡着时饥饿回升的倍数（默认 0.5）
  // 互动
  patEnabled: false,         // 关掉 → 头像不吃点击（默认 true）
  patCooldownMs: 3000,       // 两次摸头之间的冷却（默认 1500）
  bubbleEnabled: false,      // 关掉 → 不说话（默认 true）
  bubbleTtlMs: 4000,         // 一句台词挂多久（默认 2600）
  bubbleMinGapMs: 8000,      // 两句普通台词之间至少隔多久（默认 4000）
  dragEnabled: false,        // 关掉 → 卡片钉死在右下角（默认 true）
  // 成就 / 每日任务
  achievementsEnabled: false, // 关掉 → 不解锁、不渲染徽章与面板（默认 true）
  achievementSnacks: 0,      // 每解锁一个成就送几格零食（默认 1；0 = 只给徽章）
  dailyEnabled: false,       // 关掉 → 不记进度、面板里也没有任务段（默认 true）
  dailyQuestExp: 0,          // 每完成一条任务给多少经验（默认 30）
  dailyQuestSnacks: 0,       // 每完成一条任务给几格零食（默认 1）
  // 食性偏好与暴食

## 计算规则

```
combo.tick():  now - last > 5000ms → count = 0;  count = min(count + 1, 10);  last = now
multiplier  =  1 + 0.2 × count                          （count 已封顶 10 ⇒ 上限 3.0x）
taste       =  1.3（吃到最爱） | 0.75（同一种连着第 9 口起） | 1（其余）
food        =  clamp(round(floor(2.5 × log2(1 + tokens / 60) + 0.5) × taste × 暴食1.2) + floor(count / 2), 1, 30)
                 ↑ 主项：token 量级                  ↑ 口味       ↑ BUFF     ↑ 连击加成 0..+5
vitalFactor =  (0.8 + 0.4 × mood / 100) × (energy < 25 ? 0.85 : 1)      （0.68 ~ 1.2）
exp         =  max(1, floor(baseExp × multiplier × vitalFactor × 暴食2 + 0.5))
pet.feed:      hunger = max(0, hunger - food);  exp += exp;  exp ≥ level×100 时升级
             （喂之前先结算空闲期的饥饿 / 心情 / 精力：见下文「心情、精力与睡眠」）
```

**食物量走对数曲线**，不是策划的线性式。线性 `tokens / 100` 配上 `[1, 15]` 的夹取等于把 token 量级抹平：1450 token 就顶格，之后 6KB 和 60KB 的工具结果一样大；反过来 20 token 和 300 token 都保底 1。改成「token 每翻一倍多给 2.5 份」之后，从几十 token 到几十万 token 全程都分得出大小：

```
tokens     20   60   120   200   500   800  2000  5000  20k   60k   200k
food        1    3     4     5     8    10    13    16   21    25     29
```

**连击对食物量改成加法**（`+floor(count/2)`，即 0..+5）：乘法的 `×3.0` 会盖过 token 量级本身的差别，让「连击密度」而不是「消耗量」成为主导项。连击**倍率仍然乘在经验上**，所以连击的存在感转移到升级速度和特效上。

Combo 视觉等级：`1-3 → normal`（白字）、`4-6 → gold`（金字 + 轻微震动 + 金色光晕）、`7-10 → epic`（彩虹渐变 + 强震 + 光环脉冲 + 大字号）。

### 食物档位：吃的东西本身体现消耗量

除了份数，**食物的图标和字号也随 token 量级变**（`foodTierOf`）。阈值取曲线上 4 / 10 / 16 份的断点：

| 档位 | tokens | 字号 | `user_input` | `generation` | `tool_result` |
|---|---|---|---|---|---|
| `tiny` | < 120 | 16px | 🌱 | 🍤 | 🍢 |
| `small` | 120 ~ 800 | 22px | 🥕 | 🐟 | 🍖 |
| `large` | 800 ~ 5000 | 30px | 🌽 | 🐠 | 🍗 |
| `feast` | ≥ 5000 | 38px + 暖色光晕 | 🍉 | 🐋 | 🍲 |

`small` 档保留三个触发源原本的 🥕/🐟/🍖，所以「看图标认触发源」这个特征没丢；档位走食物元素的 `data-size`，与管轨迹的 `data-flight` 正交（一个改字号、一个改动画名）。

### token 数直接显示

- **飘字**：`+13 🐠 · 2.0k tok  +3 ⭐`；
- **卡片**（展开时）：`消耗 12.3k tok · 🥕2.1k 🐟8.0k 🍖2.2k` —— 总量 + 三个源各自的累计；
- **tooltip**：累计喂食次数后面跟累计 token。

数字统一走 `formatTokens`（`999` / `1.2k` / `12.3k` / `1.2M`，整千不留 `.0`）。

### 饥饿回升

`hungerRegenPerMin`（默认 2）让 hunger 按空闲时长回升，封顶 100。实现是**惰性结算**：`store.feed` 在算这一口之前先把上次结算到现在的量补上，不用常驻定时器；overlay 另挂一个 10 秒的 `setInterval` 只为让空闲时的进度条也会动（挂在组件上，卸载即停）。`hunger` 始终是整数，小数部分存在 `hungerCarry` 里攒着。

设成 0 就退回策划原本的「只降不升」。

三阶段动画沿用策划给的 keyframes（仅加 `dshpet-` 前缀）：食物飞入 600ms → 宠物 `eat-bounce` 400ms → 飘字 `float-up` 1200ms（延迟 600ms 起），总时长 2200ms = 特效 TTL。策划只写了「轻微震动 / 强震」没给 keyframes，`shake-light` / `shake-strong` 是本实现补的。系统开了「减少动效」时全部动画关闭。

### 主动喂食：零食

饥饿回升开着的时候，宠物空闲久了会一路饿到 100，而**原本唯一的喂食途径是 Agent 干活** —— 不跑任务就只能看着进度条见底。所以卡片上加了一个 🍬 按钮，`store.snack()`：

```
snack():  pet = 结算饥饿回升(now);  snacks = 结算零食回格(now)
          snacks <= 0 → 落回结算结果，返回 false（按钮此时本来就是禁用的）
          pet.feed(food = 15, exp = 1);  snacks -= 1;  totalFeeds += 1
```

| 键 | 默认 | 含义 |
|---|---|---|
| `manualFeedEnabled` | `true` | 关掉就不渲染按钮，`store.snack()` 直接返回 false |
| `manualFeedFood` | `15` | 一口零食顶多少饥饿（固定值，不走 token 曲线） |
| `manualFeedExp` | `1` | 一口零食给多少经验（`0` = 不给） |
| `manualSnackMax` | `5` | 零食格数上限 |
| `manualSnackRegenMs` | `45000` | 多久回一格（`<= 0` 视为「永远满格」） |
| `hungryAt` | `80` | `hunger ≥` 这个值就算「饿了」，触发下面那组警告表现 |

- **零食库存限流**，不是冷却。格数攒在 `state.snacks` 里，`manualSnackRegenMs` 回一格，**离线期间照攒**（和饥饿回升同一套惰性结算，上限就是格数上限，不需要另设 cap）。这样出门一天回来能连点 5 口、一次 75 点把饿惨的宠物救回来，而点着不放的持续速率只有 1 exp / 45s —— 一级要 100 exp，刷不出什么。
- **不进 combo**：`snack()` 不碰 `combo.tick`。否则手点五下就能把连击顶到 ×2.0，让后面 Agent 真喂的那一口白拿倍率。手喂的飘字因此固定是 `normal` 档。
- **不进 token 统计**：`totalTokens` / `tokensBySource` 一个字节不加 —— 零食不是 Agent 的消耗，混进去会污染「消耗 xx tok」那块面板。飘字也因此不写 token 段，是 `+15 🍬  +1 ⭐` 而不是 `… · 0 tok`。
- **食物档位固定 `small`**：`foodTierOf` 那张表按 token 量级分档，而零食没有 token 可言，所以图标永远是 🍬、字号永远是 22px，也不走会话区飞行（`LOCAL_FLIGHT`，就地飞入）。
- **按钮是卡片的第三个子节点**（`[头像][meta][🍬]`），所以**折叠状态下也在、也能点**（折叠只藏 `.dshpet-meta`）。卡片本身的 `onClick` 是折叠/展开，按钮的 `onClick` 里 `stopPropagation()` 拦住冒泡，否则喂一口顺手把卡片折了。`.dshpet-snack` 要单独写 `pointer-events:auto`（`.dshpet-root` 整体是穿透的）和 `font:inherit`（`<button>` 不继承宿主字体）。
- **饿了的警告是纯表现层的**，三处 + 一个表情：`.dshpet-card[data-hungry]` 边框转红、`.dshpet-bar-full[data-low]` 把橙色换成红色、按钮 `data-urge` 上一条 1.4s 的缩放脉冲、鲸鱼把嘴型换成向下的弧且腮红变淡（`excited` 优先 —— 正被猛喂的时候不摆脸）。`dshpet-snack-urge` 也在「减少动效」的关闭名单里。

`effectsEnabled: false` 现在只关飞行特效，**宠物卡片（以及上面的喂食入口）仍然注册**。之前是把整个 overlay 的注册包在这个开关里的，和文档写的「只留宠物卡片」不一致，也会让新按钮在关特效时点不到，一并修了；飞行特效由 `feed` / `snack` 里各自那层守卫关掉。

### 心情、精力与睡眠

策划给了 `mood` / `energy` 两个字段和 0-100 的范围，没给任何变化规则。本实现补了一套：

```
settleVitals(now):   过去的分钟数 dt = (now - lastRegenAt) / 60000
  hunger  += dt × 2         × (睡着 ? 0.5 : 1)                 封顶 100
  mood    -= dt × 0.4       - (hunger ≥ 80 ? dt × 2.5 : 0)     夹在 0..100
  energy  += dt × 1.2       × (睡着 ? 3 : 1)                   夹在 0..100
喂食那一刻:  mood += 2;  energy -= 3（手喂的零食不耗精力——那不是干活）
摸头:        mood += 6（1.5s 冷却）
```

- **和饥饿回升同一套惰性结算**：三个量共用一个锚点 `lastRegenAt`，`feed` / `snack` / `pat` / 10 秒的 tick 各自在动手前先补一次，没有常驻定时器。三个量都保持整数，小数部分各存在 `hungerCarry` / `moodCarry` / `energyCarry` 里攒着，所以「每分钟 0.4」这种慢速率不会被取整抹掉。离线期间照结算（同一个 `offlineRegenCapMs` 上限），所以出门一天回来它是饿的、心情低的、但精力满的。
- **心情和精力真的影响数值**：`vitalFactor`（见上文「计算规则」）把经验乘上 0.68 ~ 1.2 —— 心情满 ×1.2、心情 0 ×0.8，精力见底再叠一个 ×0.85。所以「养得舒服」这件事有回报，而回报上限刻意做得小（比连击的 3.0x 小一个量级），不至于让空闲一晚上变成必须的操作。
- **睡眠**：`now - lastFeedAt > sleepAfterMs`（默认 5 分钟；`energy < lowEnergyAt` 时按一半算）就睡着，睡着期间精力回得快三倍、饿得慢一半。任何一次喂食 / 手喂 / 摸头都立刻叫醒并打个哈欠。
- **睡着是瞬时态，不进存档**：`asleep` 是从 `lastFeedAt` 算出来的，落盘的是 `lastFeedAt` 本身。这样刷新页面不会把一只睡着的鲸鱼叫醒。
- 表现层：卡片 `data-asleep`、头像旁边一串飘 💤（`.dshpet-zzz`）、鲸鱼闭眼（眼睛换成两条弧）+ 平嘴，另有 `moodSadAt` 以下的委屈脸。都在「减少动效」的关闭名单里。
- 卡片上多了一行紧凑的 `😊 82 · ⚡ 64`（`.dshpet-vitals`），脸随心情换（😄 / 😊 / 😐 / 😢 / 😴）；面板里是两条完整的进度条。`vitalsEnabled: false` 时这一行不渲染，两个数字也纹丝不动（退回策划的静态展示值）。

### 挑食与暴食 BUFF

```
taste:   吃到 favoriteSource（默认 tool_result） → ×1.3
         连着吃同一种超过 boredomAfter（默认 8）口 → ×0.75（favoriteBonus 之后再乘）
         换一种口味立刻清零重新数
frenzy:  连击顶格（count ≥ maxCombo）→ 开一段 frenzyMs（默认 15s）的 BUFF
         期间 exp ×2、food ×1.2；期间再顶格就从那一刻重新算 15s
```

- **给顶格一个理由**：连击封顶在 `maxCombo`，顶格之后再密的工具循环也没有额外回报。暴食 BUFF 把「顶到格」变成一个事件：卡片红边 + 连击徽标写成 `×3.0 🔥×2`，一段限时的双倍。开 BUFF 的那一口自己**不享受**双倍（BUFF 是这一口的结果，不是它的加成）。
- **挑食是为了让口味有意义**：三个源在食物量上原本只差图标。加了「最爱 +30% / 连着 9 口 -25%」之后，穿插着来比一路刷同一种更划算，而这恰好就是一轮正常的 Agent 循环（输入 → 生成 → 工具）的样子。口味计数只跟着 Agent 的喂食走，手喂的零食不算一种口味。
- **BUFF 是瞬时态**：`state.buff` 不落盘（刷新后连击本就该断），到点由一个一次性 `setTimeout` 清掉，同时也在惰性结算里兜一次（定时器被后台标签页拖慢时不至于赖着不走）。
- `pickyEnabled: false` 把 `taste` 钉在 1，`frenzyEnabled: false` 不再开 BUFF —— 两个都关就完全退回上文那条不含口味与 BUFF 的食物公式。

### 摸头、台词气泡、拖动

- **摸头**：头像的 `onClick` → `store.pat()`，冒一颗 💗（走通知类特效那条管道，`normal` 档）、涨 `moodPerPat` 点心情、`pats + 1`（有个成就看它）、叫醒它、说一句。`patCooldownMs`（默认 1.5s）的冷却挡住「按住不放刷心情」—— 心情有经验加成，没有冷却就等于点出经验来了。头像的 `onClick` 里 `stopPropagation()`，否则摸一下顺手把卡片折了。
- **台词气泡**：`state.bubble` 一条，挂在卡片上方（`.dshpet-bubble`，带 `aria-live="polite"`）。`bubbleTtlMs` 到点由一次性定时器清掉，不落盘。场合分三类：
  - **从池子里挑一句**（`BUBBLE_LINES`，27 档）：三个喂食源、大餐、最爱、吃腻、暴食、饿了、零食、睡着、睡醒、摸头、连着摸头、进阶、成就、任务、技能升级，外加状态派生的四档（普通升级、连击升档、吃饱、困了）、心情跌破线，关怀里的深夜与久坐，以及情绪三维各一档（好奇 / 得意 / 担忧）。每档 3–7 句；天天在说的那些（三个喂食源、摸头、零食、大餐、最爱、吃腻、暴食、饿了、睡醒、睡着）都有 6 句以上，只在关键时刻响一次的（进阶 / 成就 / 任务）少一些。
  - **动态文案**（`ADVICE_LINES` / `CHAT_LINES`）：四条提示（同一文件反复改、连续报错、同一工具连着挂、终于跨过去了）和四句闲聊（好久不见、又是这个文件、这个工具你用了多少次、又到你干活的点了）—— 它们要往里填当下的事实，所以是函数而不是池子。
  - **挑句子的办法**是 `pickLineIndex`：把气泡的序号做一次散列当「随机」，再从「除了上一句之外」的 `len-1` 个位置里选，所以既不会连着蹦出同一句，也**不用 `Math.random()`** —— 同一串事件放两遍，说出来的话一模一样，冒烟测试才断言得动。
  - 散列用的是 **murmur3 的收尾函数（fmix32）**，不是随手一个 xorshift。种子是 1、2、3… 这种紧挨着的小整数，xorshift 出来的低位跟输入的低位几乎是线性关系，`% len` 之后周期短到肉眼可见 —— 第一版就在 3 句的池子上排成了「0,2,0,2,0,2…」，中间那句 6000 次里只说了 187 次。fmix32 的两次乘法把高位的熵搅进低位，各档池子的偏差在 7% 以内。冒烟测试直接量这件事（见下文），不然「说的话在池子里」这种断言全绿也发现不了。
- **谁能抢到那个气泡位**：只有一个位子，所以定了个优先次序。日常场合受 `bubbleMinGapMs`（默认 4s）限流，否则一轮工具循环会把气泡刷成弹幕；进阶 / 成就 / 摸头 / 睡醒 / 技能升级 / 升级这些「大事」不受限流管。关怀那几句（`CARE_KINDS`）排在日常台词**前面**、并且谁都不许顶掉它（`careHolds`，连睡醒那个哈欠都得让路）—— 它半小时才够格说一次，被顶掉那道冷却就白烧了。提示（advice）反而**受**限流，还额外多一道自己的冷却，而且提示说出来了就不再搭话（闲聊只在提示没说出口时补位）。情绪三维那三句（`DIM_LINE_KINDS`）排在日常台词**之上、提示之下**：它们照常受限流，但一旦占着位子，紧跟着来的提示可以不等限流直接顶掉它 —— 一次工具调用会同时推好奇心和查提示，两件事常常落在同一毫秒里，光靠时间窗分不开谁该说。反过来不行，日常台词顶不掉它（「我有点担心你」比「好吃！」值钱）。
- **拖动**：`pointerdown` 记下起点 → `pointermove` 把位移写进 `state.pos` → `pointerup` 结束并落盘。整层（`.dshpet-root`）走一个 `transform: translate(dx,dy)`，所以卡片、特效、气泡一起走，不用给每个部件都算位置。监听器挂在 `window` 上、松手即摘（指针拖出卡片外也不掉）。
  - **边界**：`clampPos` 保证卡片至少留 48px 在视野里（量不到视口时按 1920×1080 兜底），所以拖到屏幕外面也找得回来。
  - **拖完那一下点击不算点击**：浏览器在 `pointerup` 之后还会补一次 `click`，卡片的折叠与头像的摸头都先问一句 `store.dragged()`（读一次就清），否则每次拖动都顺手折叠 / 摸一下。位移超过 4px 才算「拖过」，所以正常点击不受影响。
  - `.dshpet-root` 整体 `pointer-events: none`，能拖是因为卡片自己 `pointer-events: auto`；拖动期间卡片 `data-dragging` 换成 `cursor: grabbing` 并停掉过渡。

### 成就、每日任务与连续到访

| 成就 | 条件 | | 成就 | 条件 |
|---|---|---|---|---|
| 🍼 第一口 | 吃到第一口饭 | | 🌌 百万吞吐 | 累计消耗 1M token |
| 🍱 尝遍三味 | 三种食材都吃过 | | 🍚 百口之家 | 累计喂食 100 次 |
| 🔥 满连击 | 把 Combo 打到顶格 | | 🤍 老朋友 | 摸头 50 次 |
| 🍲 大胃王 | 一口吃下 `feast` 档的大餐 | | 📅 三日之约 | 连续 3 天来喂它 |
| 💠 十万吞吐 | 累计消耗 100k token | | 👑 传说降临 | 养到 Lv.10 传说档 |
| 🗓 一周之约 | 连续 7 天来喂它 | | 🧰 老手 | 跨过 50 次工具报错 |
| 🎓 出师 | 任意一门技能练到满级 | | 🔭 十万个为什么 | 把好奇心顶到满格 |

每日任务三条：🍽 今日喂食 10 次、🛠 今日 5 次工具结果、🔥 今日打到 7 连击。每条给 `dailyQuestExp`（默认 30）经验 + `dailyQuestSnacks`（默认 1）格零食；每个成就给 `achievementSnacks`（默认 1）格零食。

- **成就表是 `ACHIEVEMENTS` 常量**：每条一个 `test(state, config)` 谓词，`checkAchievements` 在每次喂食 / 手喂 / 摸头之后跑一遍，只补新解锁的。判定读的是当场的状态快照（含 `comboCount` / `foodTier`），所以「满连击」「大胃王」这种瞬时条件也能判。后四条是被**工具调用**推动的（技能满级 / 跨过 50 次报错 / 好奇心满格），所以 `observeTool` 与 `observeToolResult` 也各查一遍 —— 不查的话它们要等到下一口饭才认，看起来像坏了。这两条路上的快照里 `comboCount` 是 0、`foodTier` 是 null，而那两条瞬时成就本来就只在 `feed` 里才可能成立，所以不会互相干扰。
- **没有哪条成就读钟点**：条件全部落在存档里的累计数字上。这不是巧合而是规矩 —— 「凌晨三点还在写代码」那种成就一旦存在，翻历史记录时就有可能凭空解锁（判定时刻和事件时刻是两回事）。
- **解锁与达成走的是特效管道**：`appendNotice` 产出一条带 `text` 的特效（成就是 `epic` 档的彩虹大字，任务是 `gold`），所以自动继承 TTL、「减少动效」降级和就地飞入 —— 和进阶那条金环是同一个口子。
- **跨天靠日序号**：`dayIndexOf(ms)` 把时间戳按**本地时区**折成天数，`daily.day` 对不上就换一份空进度（惰性结算，10 秒的 tick 也会推）。不用 `toDateString()` 之类的字符串比较，免得跨年跨时区出岔子。
- **连续到访只在真的喂食时推进**：`bumpStreak` 比较 `streakDay` 与今天 —— 同一天不动、差一天 `+1`、差更多从 1 重新数。光是开着页面让 tick 跑不算「来过」。
- **面板是懒渲染的**：卡片上那颗 🏅（`.dshpet-badge-btn`，同样 `stopPropagation`）切 `state.panelOpen`，开了才渲染 `.dshpet-panel`（状态条 / 今日任务 / 技能 / 记忆 / 成就格子五段，所以面板自己 `max-height: min(70vh, 520px)` 加纵向滚动）。卡片本身只排已解锁的徽章，没解锁的留在面板里（悬停看解锁条件），否则卡片会被十个灰格子撑宽。
- **`renderPanel` / `renderBubble` 是普通函数不是组件**：它们渲染在卡片之前，做成组件会让「卡片里第一个函数型节点就是鲸鱼」这个前提失效（冒烟测试就是这么找鲸鱼的），也没必要 —— 它们没有自己的状态。
- `achievementsEnabled` / `dailyEnabled` 各自能关；两个都关就不渲染 🏅 与面板。

### 技能：你用哪类工具，它就往哪个方向长

四条技能，靠一张**静态映射表**（`TOOL_SKILL`）把工具名分过去：

| 技能 | 图标 | xp 来源 |
|---|---|---|
| `coding` 编码 | 💻 | `read` `write` `edit` `str_replace_editor` `lsp` |
| `research` 探索 | 🔍 | `glob` `grep` `web_search` `web_fetch` `read_image` `workspace`，以及**所有不认识的工具** |
| `debug` 调试 | 🐛 | `bash` `pwsh` `terminal_*` `job_*` |
| `writing` 表达 | ✍️ | `todo_write` `plan` `report` `skill` `subagent` `send_message` `list_agents` `interrupt_agent`，外加每条 generation 事件的 `min(5, floor(outputTokens / 2000))` |

```
一次工具调用            → 对应技能 +1 xp
Lv.L → Lv.L+1 需要      L × skillXpPerLevel（默认 20）点，等级上限 skillMaxLevel（默认 10）
满级后                  xp 停在「差 1 点」，不再溢出
```

- 攒到 Lv.10 约要 900 次同类调用 —— 这是长期目标；Lv.2 只要 20 次，一个 session 就够，因为提示能力挂在 Lv.2 上（见下文）。
- 升级复用通知管道：`appendNotice(…, "技能 · 编码 Lv.3", "skill", "gold")` + 一句强制台词，所以自动继承 TTL、「减少动效」降级和就地飞入。
- **技能不碰任何数值曲线**：食物量、经验、心情一点没动。它的回报是解锁提示、面板可见，以及将来的进化方向（`skills[key].{level,xp}` 的形状就是为了那一步留的）。
- 未知工具（MCP、外部插件）落 `research`：「探索不认识的东西」是四条里最贴近的一条，也免得每加一个工具就要改表。

### 宠物记忆：它记得你常改哪个文件

存档里多一份 `memory`，全部**有界**，撑不爆 localStorage：

```
files:  [{ name, count }]   只留 basename、截断 40 字；最多 memoryFileTop + 4 行
tools:  [{ name, count }]   最多 12 行
hours:  [24 个整数]          按本地小时的活动直方图
bornDay: 日序号              第一次见面（老存档兜底为今天）
errors / recoveries: N       报过多少次错、又从错误里走出来多少次
```

- **只存 basename**：够用来说「`client.js` 改到第 3 次了」，又不把目录结构落进浏览器存储。
- **满了挤掉 count 最小的那行**（同分挤最旧的）—— 所以这是一份**近似**的记忆：常改的留得住，冷门的会被忘掉。刻意如此，不是 bug。
- `recoveries`：`tool/result` 报错时记下**是哪个工具**（用 `toolCallId` 回查 `tool/call` 的 name，表上限 64 条），**同一个**工具下一次成功才 +1。换个工具成功不算「跨过去了」。
- `bornDay` 消毒时不只夹范围：`0` / 负数会被夹成 0，面板上就成了「相处 20460 天」，比没这个字段更糟；落在「有意义的过去」之外就当作没记过，重设成今天。
- 面板多一段：`记忆 · 相处 12 天` + `📄 常改 client.js(9) smoke.mjs(4)` / `🔧 最常用 bash(31)` / `🕘 常在 21-23 点干活` / `💪 跨过 7/9 次报错`。什么都还没记下时写一句「还在慢慢认识你」。
- **「相处 N 天」按 `lastFeedAt` 算而不是 `Date.now()`**：`renderPanel` 得是状态的纯函数（同一份状态渲染两次必须得到同一块界面），顺手也让冒烟测试不跟着挂钟走。
- 「常在几点干活」是在 24 格直方图上滑一个**环形的 3 小时窗口**取最大，所以 `23-1` 这种跨午夜的时段也说得出来。

### 真实辅助能力：几句真的有用的话

四条提示，各自要求对应技能 ≥ `adviceMinSkillLevel`（默认 2），共用 `adviceCooldownMs`（默认 60s）冷却，并且仍然受 `bubbleMinGapMs` 限流：

| 提示 | 技能 | 触发 | 文案 |
|---|---|---|---|
| 同一文件反复改 | `coding` | 本次会话内同一 basename 的 `write` / `edit` / `str_replace_editor` 累计到 `adviceRepeatEditAt`（3）的整数倍 | 「`client.js` 改到第 3 次了，跑个测试？」；第 6 次起换成「改了 6 次还没好，是不是卡住了？」，第 9 次起「已经第 9 次了…要不先想清楚再动手？」 |
| 连续报错 | `debug` | 连续 `adviceErrorStreakAt`（3）条 `tool/result` 带 `error` | 「连着 3 次报错了，先看看上一条错误？」 |
| 同一个工具连着挂 | `debug` | 同一个工具名连续失败 ≥ 2 次（`toolFailStreak`） | 「`bash` 连着挂了 2 次，换个思路试试？」 |
| 终于跨过去了 | `debug` | 刚报过错的那个工具这次成了（就是 `recoveries` 那一刻） | 「`bash` 终于成了！这道坎跨过去了」 |

- 「各种工具轮着挂」和「同一个工具连着挂」是两种不同的卡法，所以 `errorStreak` 与 `toolFailStreak` 各记一份：前者该看上一条错误，后者该换个思路。前者优先。
- 最后那条是这一整套里唯一一句**正面**的提示 —— 只报忧不报喜的伙伴挺让人烦的。
- 「同一文件改了几次」的计数器是**会话内瞬时态**，不落盘：这句话说的是「你现在正卡在这个文件上」，跨天累计出来的次数没有这个意思。
- 错误连击成功一次即清零。
- 气泡带 `data-kind="advice"`，CSS 给它一道暖色左边框 + 加粗，和普通台词区分开。
- 睡醒那句在「相处 ≥ 3 天」时换成带天数的动态句（「又见面了，这是第 12 天…」）—— 记忆除了进面板，也进台词。
- `observeToolResult` 排在 `feed` **之前**跑：同一瞬间只能冒一个气泡，提示应该赢过「吃到最爱」那种日常台词（`tool/result` 既喂食又要看成没成，所以这两件事撞在同一条事件上）。靠的是 `bubbleMinGapMs` —— 提示先说完，紧跟着那句日常台词就被限流挡住了。

### 关怀与闲聊：它主动开口的那几句

上面那四条是「你好像卡住了」，这一类是「它在看着你」。四种场合，都走 `careCooldownMs`（默认**半小时**）这一道冷却 —— 这些话没有信息量，稀有才不烦人：

| 场合 | 触发 | 文案 |
|---|---|---|
| 深夜 | 本地时间落在 `careNightFrom`–`careNightTo`（默认 1–4 点，含两头；From > To 表示跨午夜） | 「这么晚还在写代码？」（池子里 4 句） |
| 久坐 | 一段不间断的活儿干到 `careMarathonMs`（默认 2h）—— 同一段只劝一次 | 「歇会儿吧，你坐了好久了」（池子里 4 句） |
| 好久不见 | 离开超过 `careComebackMs`（默认 8h）之后的第一次互动 | 「你去哪儿了…我等了 9 小时」 |
| 引用记忆搭话 | 常改的那个文件（count ≥ 5）/ 常用的那个工具（count 每满 10 次）/ 常干活的那个时段 | 「又是 `client.js` 啊」「你已经用了 20 次 `bash` 了」「又到你干活的点了（21-23 点）」 |

- **「一段不间断的活儿」怎么算**：`activeSince` 在「距上次喂食超过 `sleepAfterMs`」时重新起算，所以「你坐了两小时」说的是真的连续两小时，中间歇过就从零开始。
- **「离开了多久」用的是没被截断的时长**：离线结算把饥饿封在 `offlineRegenCapMs`（24h）是为了不让它饿死，可「你离开了三天」这件事本身值得念一句，所以这句话另算一份。
- 关怀排在喂食那句日常台词**前面**（见上面「谁能抢到那个气泡位」）。这一条是量出来的：排在后面的话，喂食一稀疏（纯聊天、没有工具循环）日常台词次次都说得出口，于是深夜那句永远不响。
- 闲聊只在提示没说出口时补位（`if (patch.bubble === undefined) chatMemory(...)`）：一句真有用的话永远优先于「又是 client.js 啊」。
- 气泡带 `data-kind` 为 `night` / `marathon` / `comeback` / `chat`，CSS 给它们一道**冷色**左边框（不加粗）—— 和提示那道暖色分开：「它在关心你」和「它在告诉你一件事」得能一眼看出区别。

### 情绪三维：好奇 / 得意 / 担忧

策划想把 `mood` 拆成 happiness / curiosity / pride / concern。这里的做法是**不拆**：`pet.mood` 本身就是「开心」那一维（经验倍率、委屈脸都还是只看它），另外三维单独加三个字段。

```
好奇 curiosity  += 碰到没见过的工具 +15、没见过的文件 +15、一次探索类工具调用 +6
得意 pride      += 升级 / 进阶 / 解锁成就（每条一份）/ 技能升级 / 从一道报错里走出来  各 +20
担忧 concern    += 一条工具报错 +20；久坐 / 深夜真的劝出口那一次 / 跨过饿线那一次  各 +12
三维每分钟各 -1.2（和心情 / 精力同一套惰性结算 + 取整留余额），夹在 0..100
≥ moodDimAt（55）→ 写在脸上、并在**跨线那一次**说一句
```

- **它们一点数值曲线都不碰**。经验倍率照旧只看 mood（0.8 ~ 1.2x），食物量、饱食度、连击一个都不受影响。理由很直接：mood 已经被食物量、经验倍率、睡眠、成就绑在一起了，再往里塞三个乘数，「为什么这一口只给了 3 经验」就变成没人算得清的事。三维换来的是**表情和台词**，仅此而已 —— 所以面板上那一行刻意只报数字、不给进度条，给了条子就等于在说「这也是个属性」。
- **脸只有一张，所以有个固定的排序**。三维排在既有四种脸色（星星眼 → 睡着 → 饿脱相 → 委屈）**之后**：那四种各自对着一个真实数字（连击倍率 / 睡眠 / 饱食度 / 心情），三维只管表情，让它盖掉「睡着」会让 UI 说谎。三维之间同分时按 `MOOD_DIMS` 的数组顺序（得意 → 好奇 → 担忧）决胜，不掷骰子。
- **每一维有一张真的脸**，不是换个 emoji：`MOOD_FACE` 给出眉形（一对贝塞尔）、眼睛缩放、嘴形、要不要填充、腮红浓度。眉毛是新部件 —— 平时鲸鱼**没有眉毛**，有情绪才长出来 —— 而且它必须挂在**眼睛之外**的一层，因为眼睛那层在眨（`scaleY`），眉毛跟着眨就成了抽搐。
- **台词只在跨线那一刻说，而且不强插**（`force: false`）。一轮工具循环能把好奇心推好几次，每次都说就成了刷屏；而它没有「升级了」「解锁成就」那么值钱，抢不到气泡就算了。谁能顶掉谁见上面「谁能抢到那个气泡位」。
- **久坐 / 深夜那两下只在关怀真的说出口时才涨担忧**（半小时一次）。否则整个深夜时段每喂一口都涨 12 点，担忧会被钉在 100，另外两维永远上不了脸。
- **「新面孔」是拿记忆表比的，而且比在记账之前**（否则每个文件都是「已经见过」）。副作用是记忆表有界、会忘掉冷门的那些，所以一个被挤掉的文件再见时又算新面孔，好奇心会重新涨一次 —— 记在「已知限制」里。
- `moodDimsEnabled: false` 退回没有这条玩法的样子：三维不涨不落、脸上不写、面板里没有那一行、也不说那三句。存档里的字段照旧读写（加字段不动 `STATE_VERSION`）。

### 空闲微交互：眼睛跟鼠标 + 闲下来的小动作

```
瞳孔:     window 的 pointermove → 归一化方向 × eyeTrackMax(1.6px)
          → 写进 .dshpet-root 的 --dshpet-eye-x / --dshpet-eye-y
          鼠标停 eyeTrackIdleMs(2s) → 回正
小动作:   蹭那个 10s 的 tick；醒着、离上次互动 ≥ 12s、离上个小动作 ≥ 45s
          → 从 yawn / wag / roll / peek 里挑一个（pickLineIndex），演 1.4s
```

- **眼睛跟鼠标全程不进 React 状态**。算出来的偏移直接以两个 CSS 自定义属性写在根节点上，由 `.dshpet-whale-pupil` 的 `transform` 读走 —— 整条链上一次重渲染都没有。鼠标一动就 `setState` 会把整张卡片（连面板和徽章墙）重渲染一遍，为了两颗瞳孔挪一像素，太贵了。
- **偏移是归一化的**：只表示「往哪儿看」，不表示「离多远」，所以鼠标在屏幕另一头和在头像边上，斜视的角度一样、幅度一样。头像矩形是缓存的、最多每 500ms 重量一次 —— `pointermove` 一秒能来上百次，每次 `getBoundingClientRect` 都会强制同步布局；卡片又能被拖动，所以缓存也不能是永久的。
- **瞳孔必须单独一层**（`.dshpet-whale-pupil` 包在 `.dshpet-whale-eyes` 里面）：一个元素只有一个 `transform`，偏移写在眨眼那层上会被眨眼的 `scaleY` 整条覆盖掉。
- **小动作挂在卡片的 `data-idle` 上**，四条各只动一个部件，其中两条直接复用既有的 keyframes（摆尾 / 眨眼），只把时长压短、次数写死 —— 「待机」和「刚做了个小动作」的区别本来就只是节奏。挑哪个走 `pickLineIndex`，所以「它刚才为什么打了个哈欠」也能重放。
- **吃饭 / 摸头那一下必须把 `idleAct` 撤掉**。`.dshpet-card[data-idle=yawn] .dshpet-whale-mouth` 是三个选择器，比 `.dshpet-eating .dshpet-whale-mouth` 的两个更具体，留着一个打哈欠的嘴会直接盖掉咀嚼动画。
- **进食和摸头是二选一，不是叠着挂**：两个动画都在动头像外层的 `transform`，一个元素只有一个 `transform`。所以状态里记一个 `lastAct`（`'eat'` / `'pat'`）决定挂哪个类，外加一个独立的 `patKey` 让每一下摸头都换 key（不换 key 动画不重播）。摸头那一下更近，它赢。
- **连着摸头换一套台词**：`patRun` 数「在 3 倍冷却之内连着摸了几下」，到第 3 下起换成 `pat_more` 那一档（「还、还要吗…」）。它是会话内瞬时态，不落盘。
- **开了「减少动效」就根本不做这两件事**：`prefersReducedMotion()` 为真时 `trackEyes` 不挂监听、`idlePlay` 直接返回。样式表里那条 `@media` 只管把动画关掉，白跑一趟的回调得靠这里挡住。取不到 `matchMedia`（老浏览器 / 测试环境）当作没开 —— 宁可动起来，也别静默地把一整套表现关掉。

```

为什么是 `localStorage`：策划把宠物状态放在后端，但**不改目标仓库**的前提下没有宿主侧的持久化接缝 —— 浏览器模块白名单里没有任何存储服务，host → 浏览器的推送通道也加不了新事件（见上文）。`localStorage` 是插件已经在用的同一条缝（配置覆盖走的就是 `dsh-pet-plugin/config`）。

几个要点：

- **只存进度，不存瞬时态**：`effects` / `comboCount` / 飞行位移 / `buff` / `bubble` / `asleep` / `panelOpen` / `dragging` 都不落盘（刷新后连击本就该断，睡没睡是从 `lastFeedAt` 算出来的），`pet.name` / `species` / 头像跟配置走，也不进存档 —— 改了 `petName` 立刻生效，不会被旧存档按住。长期积累的那几样都在：徽章、当天的任务进度、连续到访、摸头次数、摆放位置、最后一次互动的时刻。
- **写入是合并的**：一轮工具循环里连续十几次喂食只写一次。`createPersistence` 用 `saveDebounceMs`（默认 1500）攒一下，并且比对序列化后的指纹，内容没变就不写。`pagehide` 与 `visibilitychange`（切后台时 `pagehide` 不一定来）时立刻 flush，`dispose()` 也 flush 一次，所以关标签页不会吞掉最后几口。写不进去（配额满 / 隐私模式）就静默放过，宠物照样能玩。
- **读入永远消毒**：`sanitizeSaved` 对每个字段单独做类型 + 范围检查（`hunger` 夹到 `0..100`、`level` 至少 1、`exp` 不超过 `level × 100`、计数不为负），越界的夹回来、类型不对的用默认值。同域下的别的东西（或手改控制台的人）写了同名键，最坏结果是宠物看起来奇怪，而不是插件崩掉。
- **版本号是逃生门**：`v` 与 `STATE_VERSION` 不一致就整份丢弃、当作新宠物。以后改状态结构时把版本号 +1 即可，不需要写迁移。JSON 坏了同理，只 `console.warn` 一次。**加字段不动版本号**：`snacks`、后来那一批（`achievements` / `daily` / `streak*` / `pats` / `pos` / `lastFeedAt`）以及 0.3.0 的 `skills` / `memory` 都是后加的，老存档缺这些字段走消毒时的兜底（零食给满格、徽章空表、任务当天新开、位置归零、四条技能都从 Lv.1 空经验开始、记忆当作今天刚认识、`lastFeedAt` 当作「刚刚被摸过」—— 否则老用户一打开页面鲸鱼就是睡着的），没必要为了「多存几个数」让所有人从 Lv.1 重来。
- **离线也会饿**：启动时按 `savedAt → 现在` 的时长补一次结算（和在线时同一套），所以出门一天回来鲸鱼是饿的、心情低的、精力满的。上限 `offlineRegenCapMs`（默认 24h），顺手兜住系统时钟往前跳的情况。零食格数、心情、精力、跨天用**同一个锚点**结算，所以离线期间饿了多少、掉了多少心情、攒了几格零食、跨了几天，是一起算出来的。
- **跨标签页跟随**：监听 `storage` 事件，别的标签页存了新进度就采纳（后写为准），两个标签页不会各养一只。采纳时 `lastRegenAt` 一起重置，免得把对方已经结算过的时间再算一遍。

关掉与重置：

```js
// 关掉持久化（回到纯内存态，每次刷新从 Lv.1 重来）
localStorage.setItem('dsh-pet-plugin/config', JSON.stringify({ persist: false }))
// 重新养一只
localStorage.removeItem('dsh-pet-plugin/state')
```

### 食物从会话区飞向宠物

食物不是在宠物脚边冒出来的，而是**从会话里事件实际发生的位置飞过去**：

```
喂食那一刻量两个矩形（都是 getBoundingClientRect 的视口坐标）
  起点  [data-conversation-scroll] 的底部区域   ← 新消息 / 新工具结果冒出来的地方
  终点  .dshpet-avatar 的中心
相减得到纯位移 → 写进食物元素的 --dshpet-dx / --dshpet-dy
  → keyframe dshpet-fly-across 从该位移飞回 translate(0,0)
```

- `[data-conversation-scroll]` 是 `ui-conversation` 的 `ConversationRoot` 挂的锚点，`ChatView`、`StatsLine`、`InputBar` 三处都在 `closest()` 它，也有测试覆盖，算是稳定契约。
- 位移量走 CSS 自定义属性，所以整段轨迹仍然只是**一条 CSS 动画**，没有逐帧 JS。
- 起点横向按 `(effectSeq % 5) / 4` 在会话区中段散开，连击时不会叠成一条线。
- 因为两个坐标都是视口坐标、只取差值，中间隔了几层定位上下文都不影响（`shell.overlay` 的 `.overlayLayer` 是 `position:absolute; inset:0`，既不裁剪也没有 transform，所以食物可以横穿整个界面）。
- **量不到锚点时**（没打开会话、布局宽高为 0、宿主改了这个属性名）自动退回策划原本的就地飞入 `fly-in`，而不是飞到屏幕外。这两条路径冒烟测试都覆盖了。
- `flyFromConversation: false` 可以整体关掉，退回就地飞入。

## 宠物形象：DeepSeek 二次元小鲸

默认宠物是 DeepSeek 的鲸鱼（`深深 / 深海小鲸`），**一整只都是内联 SVG**，画在 `lib/client.js` 的 `WhaleAvatar` 里（viewBox 恒为 `0 0 64 64`，展示边长按等级形态从 34 长到 64）。不用外链图片：插件产物是单文件 JS 塞不了资源，而 SVG 还能跟着 Combo 换表情、跟着等级换形态。

| 部件 | 做法 |
| --- | --- |
| 身体 | 圆胖椭圆 + `#8fabff → #4d6bfe → #2f4bd8` 竖向渐变（主色即 DeepSeek 品牌蓝 `#4d6bfe`），外加一圈 `#2b3f9e` 描边，赛璐璐线稿感 |
| 白肚皮 | 上沿是向上鼓的分界线、下沿沿身体轮廓的弧走（弧半径比身体小 0.7，免得盖掉下沿描边），所以是「贴在身上的肚皮」而不是浮着的白椭圆 |
| 眼睛 | 大瞳 + 两点白高光；**epic 连击时换成星星眼**（金色四芒星）并在身侧冒闪光。瞳孔单独一层，跟着鼠标偏移（见「空闲微交互」） |
| 表情 | 平时弯嘴微笑，epic 时张成 O 型嘴；情绪三维过线时换整套五官（眉毛 + 眼形 + 嘴形，见 `MOOD_FACE`） |
| 眉毛 | 平时**没有眉毛**，某一维情绪过线才长出来 —— 一对 `stroke` 曲线，三维各一套弧度 |
| 腮红 | 两坨半透明粉，进食时会「烧」一下 |
| 尾鳍 / 胸鳍 | 画在身体之下（被身体盖住接缝），各自绕自己的根部转 |
| 喷水柱 | 头顶一道细流 + 三颗水珠，循环冒出（幼崽 / 传说档没有，见下文形态表） |
| 背鳍 / 王冠 | 按等级形态出现的静态部件（成年 / 传说），见下文形态表 |

动画（全部是 CSS，没有逐帧 JS）：

| class | 动作 | 周期 |
| --- | --- | --- |
| `dshpet-whale-body` | 浮沉 + 轻微摇摆 | 3.2s 循环 |
| `dshpet-whale-tail` | 摆尾 | 1.6s 循环 |
| `dshpet-whale-fin` | 划水 | 2.4s 循环 |
| `dshpet-whale-eyes` | 眨眼（`scaleY` 压扁一瞬） | 5.2s 循环 |
| `dshpet-whale-spout` | 喷水 | 2.6s 循环 |
| `dshpet-whale-sparkle` | 闪光（仅 epic） | 1.1s 循环 |
| `dshpet-whale-mouth` / `-blush` | 张嘴 / 脸红，挂在 `.dshpet-eating` 的后代选择器上，随每次喂食重播 | 400ms / 620ms |
| `dshpet-patted` | 摸头：整只鲸被按扁一下再弹回来，挂在头像外层 | 420ms 一次性 |
| `dshpet-whale-pupil` | 瞳孔跟鼠标偏移（读根节点上的两个 CSS 变量，不是动画而是 `transition`） | 140ms 过渡 |
| `dshpet-whale-brow` | 情绪眉毛长出来（淡入 + 从眼睛那头滑上来一小段，别让它「啪」地出现） | 260ms 一次性 |
| `[data-idle=yawn]` → `-mouth` | 闲下来打个哈欠（嘴慢慢张到最大再收） | 1.4s 一次性 |
| `[data-idle=roll]` → `-body` | 闲下来侧身翻一下 | 1.4s 一次性 |
| `[data-idle=wag]` → `-tail` | 闲下来快摆几下尾巴（复用摆尾 keyframe，压到 300ms × 4 次） | 1.2s 一次性 |
| `[data-idle=peek]` → `-eyes` | 闲下来连眨两下眼（复用眨眼 keyframe，压到 700ms × 2 次） | 1.4s 一次性 |

几个实现细节：

- SVG 里一律加 `transform-box: fill-box; transform-origin: center`（`.dshpet-whale *`），否则 `transform` 的原点是 viewBox 原点而不是部件自己，尾巴会绕着整张图转。
- 头像外层 `<span>` 的 key 是 `act-<eatKey>-<patKey>`，喂食或摸头都会换 key → 节点重挂载 → 动画重播（`eat-bounce` / 张嘴 / 按扁都靠这个）。挂哪个类由 `lastAct` 二选一（`'eat'` → `.dshpet-eating`，`'pat'` → `.dshpet-patted`）：两个动画都在动同一个 `<span>` 的 `transform`，一个元素只有一个 `transform`，所以不能叠着挂 —— 摸头那一下更近，它赢。
- 闲下来的小动作挂在**卡片**上（`data-idle`）而不是头像上：四条各动一个部件，用一个属性派发比给每个部件加类干净，代价是选择器多一层、比 `.dshpet-eating .dshpet-whale-mouth` 更具体（这就是为什么喂食 / 摸头那一下必须先把 `idleAct` 撤掉，见上文「空闲微交互」）。
- 所有鲸鱼动画都进了 `prefers-reduced-motion: reduce` 的关闭名单；喷水柱靠动画才可见，关掉动画时另给它一个静态可见态。

换回 emoji 宠物：`petAvatar: 'emoji'`，此时显示 `petIcon`（默认 🐳）。

### 按等级变形态

等级是这个插件里唯一的长期积累（`level × 100` 经验一级，越养越慢），所以让长相跟着它走：4 档形态，**每档换一处剪影**，一眼认得出养到哪一档。形态表在 `WHALE_STAGES`（常量区），`whaleStageOf(level)` 从后往前找第一个够得上的门槛。

| 档位 | 等级 | 体型（边长） | 眼睛 | 皮肤（渐变上→下） | 剪影 |
| --- | --- | --- | --- | --- | --- |
| `baby` 幼崽 | 1-2 | 34px | ×1.4 | `#e2ecff → #b3c9ff → #8aa4f0` 近乎白的淡蓝 | 还不会喷水 |
| `young` 少年 | 3-5 | 44px（原来那只） | ×1 | `#8fabff → #4d6bfe → #2f4bd8` 品牌蓝 | 喷水柱 |
| `adult` 成年 | 6-9 | 54px | ×.92 | `#6f8cff → #2740c9 → #16226e` 深蓝 | 喷水柱 + 大背鳍 |
| `legend` 传说 | 10+ | 64px | ×.92 | `#5f7cff → #1b2a8f → #0b1240` 近乎海军蓝 | 金色加粗描边 + 王冠（占了喷水口）+ 大背鳍 |

- **纯表现层**：不改经验曲线、不改食物量、不改任何数值，也**不进存档** —— 等级本来就在存档里，形态是当场算出来的。改存档里的 `pet.level` 再刷新就能直接看任一档。
- **`young` 那档就是原来那只**：老用户升到 Lv.3 之前会看到一只小一号的幼崽，之后回到熟悉的样子，不会觉得「我的鲸鱼被换了」。
- **体型直接改头像边长**（`stage.size` 写成 svg 的内联 `width/height`，覆盖 `.dshpet-whale` 的 44px），viewBox 四档都是 `0 0 64 64`，所以一个路径坐标都不用动，卡片跟着头像一起长高。第一版是缩 viewBox（`-5 -5 74 74` ~ `3 3 58 58`），四档只差 13%，摆在一起根本看不出来 —— **区分度这件事上，几个像素等于没变**。也不能走 `transform`：`.dshpet-whale-body` 上挂着浮沉动画，往同一个节点写 `transform` 会被动画覆盖。
- **配色跨度拉到底**：从「近乎白」到「近乎海军蓝」，连胸鳍的填充也跟着走 `skin[2]`。只在四种蓝里挪色相是分不出来的，得靠明度。
- **王冠占了喷水口**：三尖冠的底边正好落在头顶喷水的位置，所以传说档 `spout: false` —— 两个都画会糊成一团。背鳍插在身体椭圆**之前**（和尾鳍 / 胸鳍一样），根部被身体盖住才像从背上长出来的；它和王冠都刻意做得大（背鳍约占半个身高），小一号就等于没加。
- **进阶只在跨档时飘**：`appendEvolve` 比较喂食前后的形态，跨了才走一遍现成的特效管道 —— 一条 `source: 'evolve'` 的特效（`epic` 档的彩虹大字，文案「进阶 · 成年」）+ 头像外面一圈 1.4s 的金环 `.dshpet-evolve`。普通升级（Lv.6→7）不飘，否则前期每喂几口就来一次，很快就成噪音。手喂的那一口也算数（`snack()` 同样调 `appendEvolve`）。
- **金环不占状态**：它是从 `state.effects` 里那条进阶特效算出来的，特效被 `dropEffect` 撤掉环就跟着消失，动画 `both` 收在透明态所以不会闪回。它也在「减少动效」的关闭名单里。
- **通知类飘字**：`FeedEffect` 见到 `effect.text` 就直接飘这整句，不拼 `+N 食物 · X tok +M ⭐`（进阶没有食物量可报）。这也是给以后别的通知类特效留的口子。
- 形态名进**名字行**（`深深 · Lv.6 成年`）、**tooltip**（`形态 成年 → Lv.10 传说`，最高档没有箭头那段）、**卡片的 `data-stage`**（留给 CSS 的钩子）与鲸鱼的 `aria-label`。
- **`petAvatar: 'emoji'` 不受影响**：图标是用户自己配的字形，插件不擅自按等级换。形态名 / tooltip / `data-stage` / 进阶特效仍然有效。

## 打包校验做了什么

```sh
node scripts/pack.mjs          # 或 npm run pack
```

产物落在 `dist/dsh-pet-plugin-<version>.tgz`，别人拿到后一条命令装完即用——**tarball 里是现成的产物，没有 `prepare` / `postinstall`，所以不需要 pnpm 的 `allowBuilds` 授权**（从 git 装才需要）。

脚本按顺序做六件事，任何一步不过就退出并列出全部问题：

1. **清单**：`type: "module"`、`main`、semver、`dsh.bundle.patch` 存在且指向真实文件、`dsh.client.platform === "web"`、`exports` 的三条（`.` / `./client` / `./package.json`）齐备、`files` 覆盖 `index.js` + `lib/client.js` + `cordis.patch.yml` 且没混进开发件。
2. **配置层**：`cordis.patch.yml` 里有 `- insert:`，且有一行的 `name` 等于包名——`client-modules` 的扫描以「一条活着的 entry，其 `options.name` 等于包名」为前提，名字写错插件就只是静默地不出现。
3. **产物格式**：`node --check` 过语法；`window.__ModuleLoader__.load(` / `var module = { exports: {} }` / `return module.exports` / `exports.apply =` 四件套齐备；产物里的 `id` 等于包名。
4. **产物纯净度**：扫出所有 `require("…")` 的目标，逐个比对 `PLATFORM_MODULES` 白名单。浏览器模块表里只有那十来个平台模块，require 到别的东西必然在运行时 resolve 失败——这一条是最容易在开发时不小心破坏的。
5. **冒烟测试**：跑一遍 `test/smoke.mjs`。
6. **复核 tarball**：脚本自己解开 `.tgz`（`zlib` + 手写 tar 头解析，零依赖），确认里面正好是 `files` 允许的那四个文件（`package.json` / `index.js` / `lib/client.js` / `cordis.patch.yml`——文档不在包根，不进 tarball）、没有 `test/` `scripts/` `dist/` `node_modules/`、`lib/client.js` 与本地校验过的那份逐字节相同、解压出来的 `package.json` 仍带着两个 `dsh` manifest。

其他用法：

```sh
node scripts/pack.mjs --check       # 只跑 1-5 步，不打包
node scripts/pack.mjs --out build   # 换输出目录
node scripts/pack.mjs --packer npm  # 强制 npm pack（默认 pnpm，失败自动退回 npm）
```

## 已知限制与偏离策划之处

- **宠物状态存在浏览器本地，而不是策划设想的后端**（见上文「进度落盘」）。因此它**按浏览器 + 域名分家**：换浏览器、换设备、无痕窗口、清站点数据都是一只新宠物，同一台机器上不同项目的 dsh 只要域名端口相同就共用一只。要做到跨设备的账号级进度就得改目标仓库（往 `API_REMOTE_FORWARDED_EVENTS` 里加一个事件 + 一个 host 侧 Service），本实现明确不走这条路。
- **`player_id` / `pet_id` / 多宠物没有实现**。单浏览器单宠物，`AutoFeedEvent` 的这两个字段在这个形态下没有承载对象。
- **补了饥饿回升**：策划的 `feed` 只写了 `hunger = max(0, hunger - amount)`，没有回升规则，喂几次饱食度就顶满并停住 —— 食物量的大小随即失去意义。本实现按策划「扩展点」的方向补了 `hungerRegenPerMin`（默认每分钟 +2，封顶 100，惰性结算），设成 0 可退回策划行为。
- **宠物不会饿死**：`hunger` 封顶 100 就停住，不掉等级、不掉经验、不重置 —— 这是刻意的。策划没写任何惩罚规则，本实现不发明；饿了只有表现层的提醒（红条 + 耷脸 + 按钮脉冲，见上文「主动喂食」），`hungryAt` 只决定这组提醒从哪个饥饿度开始，不带任何数值后果。
- **补了主动喂食**：策划里宠物只被 Agent 的活动喂。加上饥饿回升之后空闲期没有任何补救途径，所以补了零食按钮（`manualFeed*` / `manualSnack*`），`manualFeedEnabled: false` 可退回策划行为。它刻意不进 combo、不进 token 统计。
- **食物量是对数曲线而不是策划的线性式**，且**连击对食物量走加法**、**食物按 token 量级分四档**、**界面直接显示 token 数**。策划只写了 `tokens / tokensPerFood × multiplier` 加 `[1, 15]` 夹取，那条式子在真实用量下几乎分辨不出消耗量（见上文「计算规则」）。相关配置 `tokensPerFood` 的含义随之从「多少 token 换 1 份」变成曲线的起点尺度，默认值也从 100 改成 60。
- **补了 `mood` / `energy` 的变化规则**：策划给了这两个字段和 0-100 的范围，但没给任何变化规则。本实现补了一套（回落 / 回升 / 睡眠 / 对经验的 0.68 ~ 1.2 倍摆幅，见上文「心情、精力与睡眠」），`vitalsEnabled: false` 可退回策划的「静态展示值」。
- **睡眠、摸头、台词气泡、拖动、成就、每日任务、连续到访、食性偏好、暴食 BUFF 全是本实现补的**：策划里一个都没有。每一组都有独立开关（`sleepEnabled` / `patEnabled` / `bubbleEnabled` / `dragEnabled` / `achievementsEnabled` / `dailyEnabled` / `pickyEnabled` / `frenzyEnabled`），全设成 `false` 就退回「只有 Combo 与饱食度」的策划形态。
- **成就表与每日任务表是常量，不走配置**：和 `WHALE_STAGES` 同一个理由 —— `resolveConfig` 只做「同类型标量覆盖」的校验，塞一张带谓词的表进去等于没有校验。数值（奖励多少、任务目标）里只有奖励是配置项，任务的目标值写在 `DAILY_QUESTS` 里。
- **每日任务 / 连续到访按本地时区跨天**，`dayIndexOf` 折出来的日序号也直接落盘。跨时区旅行时可能出现「同一天算了两次」或「差一天变成差两天」，代价是连续到访断一次；换成 UTC 会让「今天」在大半个地球上跟日历不一致，本实现选了前者。
- **成就与任务只在有交互时结算**：`checkAchievements` / `applyDaily` 挂在喂食 / 手喂 / 摸头上，跨天清零挂在惰性结算上。所以「养到 Lv.10」这类成就要等下一口饭才亮 —— 不为此加常驻定时器。
- **摸头的心情有冷却，拖动会吃掉一次点击**：这两处都是刻意的取舍，理由见上文「摸头、台词气泡、拖动」。
- **升级采用扣减制**：策划只说「exp 达到 level×100 后升级」，本实现在升级时扣掉 `level×100` 并允许一次喂食连升多级。
- **饱食度 = 100 - hunger**：策划的 `hunger` 是饥饿度（越低越好），界面上显示成饱食度更直观，这是纯展示层的换算。
- **宠物形象是本实现定的**：策划没规定长相，只规定了 `eat-bounce`。DeepSeek 二次元小鲸的造型、待机动作、星星眼都是本实现补的，`petAvatar: 'emoji'` 可以退回单字形头像。
- **等级形态是本实现补的，且门槛不走配置**：策划里等级只是个数字。4 档形态（见上文「按等级变形态」）是纯表现层的补充；`WHALE_STAGES` 是常量而不是配置项 —— `resolveConfig` 只做「同类型标量覆盖」的校验，塞一张数组表进去等于没有校验，而收益只是「能自己改门槛」，不值这个复杂度。想关掉按等级变形，用 `petAvatar: 'emoji'`。
- **每条喂食事件各自成一个 Conversation Context**（`id = "seq-<seq>"`，`role` 恒为 `start`）。这样引擎对每条事件最多调一次 `start`，代价是长会话里 Context 数量与可喂事件数同阶。这些 Context 是 state-only 且 `publication: "none"`，不参与任何视图构建。
- **多了一条 keyframe，并且依赖一个宿主 DOM 属性**：`dshpet-fly-across`（食物从会话区飞来）是本实现加的，策划的 `fly-in` 原样保留作为退路。它读 `[data-conversation-scroll]` 的位置——这是插件唯一一处对宿主 DOM 的耦合。宿主要是改了这个属性名，效果会**静默降级**成就地飞入（不报错、不飞到屏幕外），把 `flyFromConversation` 设成 `false` 是同样的效果。
- **技能 / 宠物记忆 / 提示也全是本实现补的**：策划里没有这三样。三个开关（`skillsEnabled` / `memoryEnabled` / `adviceEnabled`）各自设 `false` 就退回没有它们的样子。技能刻意**不参与任何数值计算**（食物量 / 经验 / 心情都不看它），回报只有「解锁提示」和面板可见。
- **记忆是近似的，会忘事**：`files` / `tools` 两张表有行数上限（`memoryFileTop + 4` / 12），满了就挤掉 count 最小的那行，同分挤最久没碰的。常改的文件留得住，偶尔碰一次的会被忘掉 —— 这是「记忆」而不是审计日志，刻意不做无界累积（localStorage 有配额）。同理只存 basename 不存全路径：够说「`client.js` 改到第 3 次了」，也不把目录结构落进浏览器存储。
- **不认识的工具一律落 `research`**：`TOOL_SKILL` 是一张静态表，只覆盖宿主仓库里那 29 个工具。MCP 工具、别的插件加的工具都算「探索」—— 这是四条里语义最近的一条，也免得每加一个工具就得改表。想让某个工具算别的技能，得改常量表而不是配置（和成就表同一个理由）。
- **「工作时段」只按工具调用统计**：`hours` 直方图只在 `tool/call` 上打点，纯聊天（没触发任何工具的对话）不进直方图。所以它说的是「你常在几点让 Agent 干活」，不是「你常在几点开着这个页面」。
- **「同一文件改了几次」不落盘**：这个计数器是会话内瞬时态，刷新即清零。这句提示的意思是「你现在正卡在这个文件上」，跨天累计出来的次数没有这个含义。相对地，`errors` / `recoveries` 是长期累计的。
- **提示只有四条，且都要够级**：`adviceMinSkillLevel`（默认 2）+ `adviceCooldownMs`（默认 60s）+ `bubbleMinGapMs` 三道闸门叠在一起，宁可少说也不刷屏 —— 设计原则是「零打扰」。新装的宠物在攒够 20 次同类调用之前一句提示都不会说。
- **关怀与闲聊也是本实现补的，而且判断是近似的**：`careEnabled: false` 一关到底。「深夜」按**本地时区**的小时数判定（和每日任务同一套取舍，跨时区旅行时会偏一格）；「久坐」量的是「距上次喂食不超过 `sleepAfterMs` 的一串事件持续了多久」—— 你人离开但 Agent 还在跑长任务的话，它会以为你还坐在那儿。这几句台词半小时才够格说一次（`careCooldownMs`），所以撞上的那次会被丢掉而不是排队。另外这几句只挂在 **Agent 喂食**那条路上：手点零食、摸头不触发关怀（那两条是你在逗它，不是它在看你干活），所以「好久不见」要等下一条会话事件才说得出口。
- **闲聊要够门槛才开口**：常改的文件要 count ≥ 5、常用的工具要正好第 20 / 30 / 40… 次、工作时段要直方图上真有个峰。刚养的宠物什么都不会说 —— 「它记得你」得先真的记住了才说得出口。
- **情绪没有按策划拆开，三维是纯表现层**：策划想把 `mood` 拆成 happiness / curiosity / pride / concern 四维。本实现**没拆** —— `pet.mood` 继续独占「开心」这一维和它背后的全部数值（经验倍率、委屈脸、饿过头掉得快），新加的三维只管换表情、换那三句台词，一条数值曲线都不看。这样老存档、老配置、老断言全都不动，代价是三维**没有玩法深度**：顶到 100 除了换张脸和一枚成就之外什么都不给。`moodDimsEnabled: false` 一关到底。
- **被忘掉的文件再见时又算「新面孔」**：好奇心的「没见过」是拿记忆表比的，而记忆表有界、会挤掉冷门的行（见上一条）。所以一个很久没碰的文件被挤出去之后，下次再改它好奇心会重新涨一次。修掉它就得记一份「见过什么」的无界集合，那正是记忆表刻意不做的事。
- **三维那三句台词的优先级是硬编码的**：`DIM_LINE_KINDS` 里那三种排在日常台词之上、提示之下（见上文「谁能抢到那个气泡位」）。这个次序不是配置项 —— 它是「装饰性台词永远不许挤掉真有用的话」这条原则的实现，能配就等于能关掉原则。
- **瞳孔跟鼠标与闲下来的小动作，在「减少动效」下整套不做**：不是关掉动画留着算，而是根本不挂 `pointermove`、不排小动作（`prefers-reduced-motion` 为真，或 `eyeTrackEnabled` / `idleActEnabled` 为 `false`）。取不到 `matchMedia` 的环境（老浏览器 / 测试桩）当作没开 —— 宁可动起来，也别静默地把一整套表现关掉。另外瞳孔位置**不进状态也不落盘**：它只是两个 CSS 自定义属性，刷新即回正。
- **插件集变化需要重启**：`client-modules` 会永久缓存「这个包不是 web 插件」的否定判定，所以装完 / 卸完必须重启 `dsh`。
- **子 Agent 会话也会喂食**：Definition 注册在所有会话上，subagent 的事件同样计入 Combo。这是有意的（工具循环本来就是高 Combo 的主要来源）。
